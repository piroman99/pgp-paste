# pgp-paste

Маленькое GTK-окно для тех двух задач, которые в GnuPG делаются только из терминала:
**вставить чужой ключ прямо из письма** и **зашифровать/расшифровать текст** без сохранения файлов.

Проверено на Ubuntu с GNOME, Python 3.12, PyGObject 3.48, gpg 2.4.8.

## Зачем

Если у вас в системе нет Kleopatra или GPA (в Ubuntu по умолчанию их нет), то импорт ключа
выглядит так: сохранить блок из письма в файл, потом `gpg --import файл`. А шифрование —
`gpg --armor --sign --encrypt -r <отпечаток> -o out.asc in.txt`. Каждый раз.

Seahorse (стандартные «Пароли и ключи» в GNOME) импортирует **только из файла** —
вставить текст из буфера в него нельзя. Thunderbird умеет импорт из буфера, но это почтовый
клиент, и в Ubuntu он ставится как snap-заглушка.

Это окно закрывает ровно этот пробел: две вкладки, копипаст, без файлов.

## Что умеет

**Вкладка «Ключ»**

- вставить блок `-----BEGIN PGP PUBLIC KEY BLOCK-----` из письма и импортировать
- «Проверить» — показать отпечатки, uid и наличие подключа шифрования, ничего не меняя
- «Из файла…» — если ключ пришёл вложением
- «Мой ключ в буфер» — скопировать свою публичку, чтобы вставить в письмо

**Вкладка «Текст»**

- выбрать получателя из списка чужих ключей (свои ключи в списке не показываются)
- зашифровать текст, при желании подписать своим ключом
- расшифровать вставленное сообщение и увидеть вердикт по подписи
- скопировать результат в буфер

## Установка

```sh
sudo apt install gnupg python3-gi gir1.2-gtk-3.0
sh install.sh
```

Появится «PGP — ключи и шифрование» в меню приложений и на рабочем столе.

Запуск без установки:

```sh
python3 pgp-paste.py
```

Удаление:

```sh
sh uninstall.sh
```

## Как это выглядит

Скриншотов в репозитории нет намеренно: автор собирал и проверял окно в среде без
дисплея (через broadway-бэкенд GTK), снять настоящий скриншот было нечем, а рисовать
макет «для красоты» — нечестно. Запустите у себя, выглядит как обычное окно GTK3
с двумя вкладками.

## Как проверялось

Логика прогонялась end-to-end на временных связках gpg (по одной на «меня» и «коллегу»):

- импорт ключа из вставленного текста, обновление списка получателей
- шифрование → расшифровка в отдельной связке → текст совпал, подпись распознана
- подмена байта в шифртексте → «текст повреждён или подменён»
- чужое сообщение → «нет подходящего секретного ключа»
- пустой ввод и не-PGP текст → внятные сообщения вместо трейсбеков
- минимальный размер окна 794×641 — влезает в 1366×768

## Безопасность

- приватные ключи окно **не создаёт и не экспортирует**; работа идёт с вашей обычной связкой `~/.gnupg`
- «Проверить» импортирует во временную связку во временном каталоге и удаляет её — ваш keyring не меняется
- пароль на ключе спрашивается штатным pinentry, окно его не запоминает
- `--trust-model always` используется только чтобы gpg не отказывался шифровать на ключ
  без выставленного доверия. **Доверие всё равно нужно проверять руками**: сверять отпечаток
  с владельцем по другому каналу (голосом, лично), а не по тому же чату, откуда пришёл ключ.
  Иначе подмена ключа проходит незамеченной и вся схема ничего не стоит.

## Требования

- Linux с GTK3 (проверено на GNOME; на KDE/XFCE должно работать, но не проверялось)
- `gpg` 2.2+
- Python 3.8+, PyGObject, GTK3
